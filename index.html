    fab679/datastreamdb

    A graph database inside your process.

    DQL and GraphQL, embedded in Rust, TypeScript, Python, or C.

    Start embedded Run the servers
    cargo add datastreamdb-core

    One engine, two places to run it

    The same schema, query planner, posting store, and GraphQL layer run in both modes. Embedded drops the network, not the engine.

    Embedded
    An Instance inside your application. No ports, no sidecar, no cluster to operate. Single-node, one writer.
    Standalone
    zero and alpha processes over HTTP or gRPC, with raft groups, ACL, and namespaces.

    Relationships, not foreign keys

    Genres are nodes. Cast roles live on the edge. Traverse either direction without a join table.

    schema 
    genre: [uid] @reverse .
acted_in: [uid] @reverse .
type Movie {
  name
  genre
  acted_in
}
    query 
    {
  movie(func: eq(name, "The Matrix")) {
    name
    genre { name }
    cast: acted_in @facets(role, billing) { name }
  }
}

    Start in the language you already have

    Four bindings over one Rust core. Each one opens an isolated instance and runs the same DQL.

    BindingInstallOpen
    Rust cargo add datastreamdb-core Instance::open(cfg)
    TypeScript npm install @datastreamdb/core new Instance('{}')
    Python pip install datastreamdb Instance("{}")
    C release archive datastreamdb_open("{}", &h)
